# 0015. 개인 프로젝트여도 폴더 구조와 디자인 시스템을 갖춘다

- 상태: 채택
- 날짜: 2026-11-22
- 결정한 사람: Justin

## 맥락

하루 사이에 기능이 빠르게 늘면서 공용 코드가 `src/` 바로 아래에 흩어졌고, 색과 모양 값이 스타일 파일 하나에 섞여 있었다.

## 결정

개인·사이드 프로젝트여도 최소한의 구조를 갖춘다.

- 공용 코드는 `src/lib/`, 화면 조각은 `src/components/`, 주소는 `src/pages/`, 서버 쪽 코드는 `functions/`.
- 색·모서리 같은 값은 `src/styles/tokens.css` 한 곳에만 정의하고, 규칙은 [디자인 시스템 문서](../design-system.md)에 적는다.
- 결정은 이 폴더에 ADR로 남긴다.

## 검토한 대안

- **지금처럼 두기**: 파일이 더 늘면 어디에 무엇이 있는지 찾기 어렵다.
- **컴포넌트 문서 페이지까지 만들기**(erp--quest-on의 `/dev/design-system`처럼): 구성 요소가 열 개 남짓이라 문서 한 장으로 충분하다. 늘어나면 다시 본다.

## 결과

- 새 색이 필요하면 구성 요소에 직접 적지 않고 토큰에 추가한다.
- 구조를 바꾸는 결정을 하면 ADR을 먼저 쓴다.
